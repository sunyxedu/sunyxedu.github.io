    Identity and the IR¶

    Speculative execution changes when work runs and which attempts are cancelled. It must not silently give a surviving logical request a different prompt, sampling draw, or observation contract. AgentIR makes these properties part of the request's identity.

    A prompt is a symbolic spine¶

    A Seq carries an immutable spine made of three kinds of segment:

    Segment Meaning Available before the producer finishes?
    Lit(atoms) Literal text or token IDs Yes
    Out(engine_node) The generated output of an engine node Its identity is available; its output may not be
    Obs(tool_node, projection_id) A named projected observation of a tool Its identity is available; its image may not be

    Adjacent literal segments are merged and empty literals removed. This canonical form prevents irrelevant construction differences from creating different prompt identities.

    An Out segment identifies the producer symbolically. Hashing a continuation therefore does not require waiting for its producer's output bytes. At execution, that output is still a real data dependency: the prompt cannot be sent until its required atoms exist.

    Separate logical requests from physical attempts¶

    An engine node's content address combines its canonical spine, model role, frozen generation parameters, sampling draw, and observation mode. Log-probability collection and tool-stream projections affect the observation contract and therefore matter to identity.

    The sampling draw contains a lexical call site and scoped occurrence, plus a lane for parallel expansion. The tracer reserves it before checking branch viability. Each loop iteration has a separate path scope, so over-unrolling a rejected tail does not shift draw numbering after the loop.

    call site + scoped occurrence + expansion lane
                     ↓
                   DrawId
                     ↓
spine + role + parameters + observation mode → NodeId
                                               ↓
                         invocation seed → sampling seed

    Different possible worlds of one hoisted continuation share the logical draw, but their different prompts produce different node identities and seeds. Reissuing the same node preserves its identity and seed while obtaining a fresh physical request ID.

    problem_key labels logs. invocation_key participates in identity scoping; pair it consistently when a controlled comparison must reproduce one logical invocation. A stable seed alone is not a proof that every engine environment emits identical tokens.

    Tool identity excludes observations¶

    A tool node is identified by its tool name, canonical JSON arguments, draw, and effect contract. Arguments containing Val objects are resolved before hashing. Invalid or non-canonical JSON is rejected; sequence handles cannot be smuggled into argument dictionaries.

    Projection names and implementations identify observation views independently of the tool body. Adding a projection must not execute the same logical body again. Each named projection is cached and evaluated once, and its image is encoded lazily when a prompt actually needs it.

    An after= edge changes scheduling order, not body identity. Likewise, an observation guess does not become the actual tool execution's identity.

    Four-valued guards¶

    A guard is a conjunction of decision literals. While evaluating it, the runtime can observe:

    Value Meaning Effect on a conjunction
    False A required alternative was rejected Dominates everything; the world cannot survive
    Pending At least one required decision is unresolved Defers failure publication because the world may still be rejected
    Failed A relevant decision failed Observable once no false or pending literal masks it
    True Every required condition is satisfied The guard permits commitment

    The precedence is false, then pending, then failed, then true. For example, a failed inner judge must not fail a program whose outer decision later rejects that entire branch. When several unmasked failures exist, decision creation order provides a stable cause.

    Decisions check their own entry guards before consuming rankings. This prevents a decision in an impossible world from publishing an otherwise irrelevant error.

    Why identity is shared with the compiler¶

    The static compiler uses the same core chunk encoders to precompute identity prefixes. It does not maintain a parallel approximation of the hashing scheme. Dynamic holes are supplied later; runtime parity tests check that finalizing a compiled prefix agrees with live tracing.

    The independent serial reference also shares identity helpers, while using different control-flow execution. That makes disagreements about which logical work survives visible instead of comparing unrelated random draws.
