    Models and vLLM¶

    AgentIR's local engine adapter targets vLLM 0.24.0. It submits independent generation requests with stable seeds and priorities, and uses vLLM's automatic prefix caching to reuse prompt work. There is no separate copy-on-write engine-fork primitive in this adapter.

    Create a runtime¶

    from agentir import SpecConfig, make_runtime

runtime = make_runtime(
    model="Qwen/Qwen2.5-0.5B-Instruct",
    max_inflight=32,
    engine_args={"max_model_len": 2048, "gpu_memory_utilization": 0.5},
    spec=SpecConfig(window=2, max_spec_inflight=8),
)

    Weights load lazily on first use or explicit warmup. Call runtime.close() when finished, or use with make_runtime(...) as runtime:. Keep runtime creation behind a Python main guard when using subprocess engines.

    max_inflight limits AgentIR requests on a physical engine. The effective capacity also respects an explicitly supplied vLLM max_num_seqs. The adapter requires priority scheduling; committed work must be able to outrank speculation.

    Choose a wire¶

    Wire Representation Use it for
    wire="text" (default) String prompt atoms Plain completion programs and text-only judge-server workflows
    wire="tokens" Exact token-ID tuples Autonomous tools and chat boundaries that must survive without decode/re-encode changes

    For chat prompts, call runtime.chat_prefix(messages, role="main", ...) and pass the result to lit inside your program. Rendering uses the selected engine's chat template. Model-specific boundaries, including Harmony token sequences, remain engine-owned.

    messages = [{"role": "user", "content": "Explain why the sky is blue."}]
prefix = runtime.chat_prefix(messages)

def program():
    return force(out_text(infer(lit(prefix), max_tokens=128)))

    The snippet assumes the corresponding DSL imports and an active runtime. The autonomous tool loop handles conversation rendering for you.

    Give models explicit roles¶

    make_runtime creates a main role and, by default, aliases judge to it. Supply judge_model for a separate judge engine. devices and judge_devices select the GPU visibility of the respective engines.

    For more roles, construct Runtime from ModelSpec and EngineSpec configurations. Unknown role names raise an error. Physical engines are deduplicated by their resolved configuration, including model, device placement, parser settings, and token drafter configuration.

    Multiple engines can share a token-wire runtime. Their token spaces must be compatible: identical model identity is a fast path; otherwise the runtime compares tokenizer fingerprints, including backend configuration and special-token IDs. Matching vocabulary size alone is insufficient.

    judge_process=True runs the judge behind a managed server process; judge_server_attach connects to an existing one. These judge-server modes require the text wire and serve the scoring workflow. They are distinct from the certified remote runtime.

    Freeze generation and template settings¶

    Sampling parameters are validated and frozen before node identity is constructed. Use max_tokens, temperature, top_p, and the other supported parameters. The DSL derives the sampling seed from identity; it does not accept an arbitrary per-call seed.

    Chat template options are also captured as canonical configuration. Supply chat_template_kwargs for the main model and judge_chat_template_kwargs for the judge. Omitted judge options inherit the main options; an explicit {} resets them.

    For constrained generation, structured accepts exactly one supported constraint kind. Capabilities are checked before a request can rely on them. A parser or template incompatibility should surface as an error, not a silently altered prompt.

    Understand event granularity¶

    With event_granularity="auto", ordinary committed generations can use terminal-only events. Requests watched by streamed projections, prefix prefetch, or bound policies need intermediate updates. Event granularity changes observation cost, not the semantic output contract.

    The adapter preserves engine-provided text sidecars where needed; decoding the same token tuple in a different context can change visible formatting. Token and text checks therefore serve different purposes.

    Distinguish two forms of speculation¶

    AgentIR speculates over agent branches. vLLM token drafting speculates over tokens inside one request. Configure drafting through the engine configuration independently of SpecConfig.enabled.

    The adapter normalizes drafter configuration into engine identity and rejects incompatible sampling options. In particular, draft-enabled requests cannot include min_p or logit_bias, even when their supplied values appear neutral. See optimization mechanisms.
