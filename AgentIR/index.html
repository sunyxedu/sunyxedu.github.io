    AgentIR 1.3.0 · Python 3.11+ · vLLM 0.24

    AgentIR documentation¶

    Speculative execution for LLM agents. Write the agent's search and selection logic in plain Python; the runtime starts possible next steps while the decision between them is still being made, then keeps the selected one and cancels the rest.

    Test-time scaling means giving an agent more compute to search for a better answer: sample several candidates, judge them, continue from the best. Every one of those judgments is a wait. While a judge model compares two answers, the next request usually sits idle, even though either answer already contains everything needed to start its continuation.

    AgentIR makes that opportunity explicit. It separates the data a request needs to be built from the decision it needs to be kept. A continuation can start as soon as its data exists; the decision only determines whether its result survives. The runtime tracks both, so an agent program written without any mention of speculation still gets it, and a verification harness can prove that the answer is byte-for-byte what the serial program would have produced.

    The idea in one example¶

    candidates = expand(prompt, 4)                      # four samples, one prefill
scores = collect([op(grade, out_text(c), pure=True) for c in candidates])
best = choose(candidates, by=op(rank, scores, pure=True), k=1)[0]
answer = infer(cat(best, lit("\nExplain the answer:")))
return force(out_text(answer))

    choose does not wait for the ranking. It returns a placeholder for "whichever candidate ranks first". When infer continues from that placeholder, the tracer registers one explanation per candidate, each carrying a condition (a guard) that says which ranking outcome would keep it. Each explanation needs only its own candidate's text to start, so the scheduler can run all four while the grader is still working. When the ranking resolves, one explanation commits and three are cancelled. force returns only the committed one.

    Every request's sampling seed is derived from its logical identity, not from when it ran, so a continuation issued early produces the same tokens it would have produced after the decision. That is what lets verification demand byte identity between speculation on and off.

    Where speculation helps¶

    Speculation pays off when a program exposes a continuation before the decision selecting it resolves, and the engine has spare capacity to run it. Candidate search (best-of-N, beam search, MCTS), judge-and-refine loops, and tool calls with predictable results all have that shape. Slow judges create the opportunity; a saturated GPU erases it. The benchmarking guide shows how to measure the difference honestly.

    AgentIR speculates over agent decisions. That is a different level from vLLM's token-level speculative decoding, and the two compose. See scheduling optimizations before comparing them.
