    Your first program¶

    This program samples four short answers, selects the most common numeric answer, and asks for a one-sentence conclusion. The last request can begin while the vote is unresolved.

    You need the local installation and a working GPU engine to run it. The complete version lives in examples/quickstart.py.

    The complete program¶

    Save the following as first_program.py in your checkout:

    import re
from collections import Counter

from agentir import (
    SpecConfig, cat, choose, collect, expand, force,
    infer, lit, make_runtime, op, out_text,
)


def extract_number(answer):
    numbers = re.findall(r"-?\d+", answer or "")
    return numbers[-1] if numbers else ""


def rank_by_vote(answers):
    counts = Counter(answer for answer in answers if answer)
    return sorted(
        range(len(answers)),
        key=lambda i: -counts.get(answers[i], 0),
    )


def program():
    prompt = lit(
        "Q: A pen costs 3 dollars. How much do 5 pens cost? "
        "Reason briefly, then give the number.\nA:"
    )
    candidates = expand(prompt, 4, max_tokens=96)
    answers = collect([
        op(extract_number, out_text(candidate), pure=True)
        for candidate in candidates
    ])
    ranking = op(rank_by_vote, answers, pure=True)
    selected = choose(candidates, by=ranking, k=1)[0]
    conclusion = infer(
        cat(selected, lit("\nSo, in one sentence:")),
        max_tokens=32,
    )
    return force(out_text(conclusion))


if __name__ == "__main__":
    with make_runtime(
        model="Qwen/Qwen2.5-0.5B-Instruct",
        spec=SpecConfig(window=2),
        engine_args={"max_model_len": 2048, "gpu_memory_utilization": 0.5},
    ) as runtime:
        print(runtime.run(program, problem_key="first-program"))

    Run it from the activated environment:

    python first_program.py

    It prints the final generated conclusion. The exact wording depends on the model and execution environment; the intended arithmetic answer is 15 dollars.

    1. Generate candidates without reading them¶

    lit creates a literal prompt handle. expand(prompt, 4) creates four separate sampling draws that share a prompt prefix. Each result is a Seq: the original prompt followed by that draw's generated output.

    Creating these handles does not require the tracer to wait for their strings. The engine can execute ready requests while Python continues building the program.

    2. Evaluate through asynchronous values¶

    out_text(candidate) describes the generated tail of a candidate. Each op waits for its input, extracts a number, and produces a Val. collect gathers those values in candidate order, and another op produces a ranking of indices.

    Both functions are marked pure=True because they are deterministic computations with no external effects. That declaration lets eligible speculative work use their results before commitment. It is a contract you provide, not a purity check performed by Python.

    3. Preserve the choice¶

    choose(..., k=1)[0] represents rank zero of an unresolved selection. It preserves all possible candidate identities until the ranking resolves.

    Passing this handle to cat and infer lets the tracer construct one continuation per possible selected candidate. Each continuation needs its candidate's output, but its prompt does not depend on the vote result. The scheduler can therefore run it early if capacity and speculation budgets allow.

    If you instead force the ranking and use ordinary Python indexing, you make selection a tracing barrier and lose this overlap opportunity.

    4. Publish one answer¶

    force(out_text(conclusion)) waits for the selected continuation and the decisions that allow it to be observed. Losing continuations do not become return values.

    This small vote is deliberately cheap, so it may leave little useful overlap. The example teaches the programming model; it is not a performance benchmark. A model-based judge or a slower decision may create a larger opportunity.

    Inspect what happened¶

    Before leaving the runtime's with block, you can inspect the invocation's ledger:

    rows = runtime.ledger_for("first-program")
print("issued speculatively:", sum(row.speculative for row in rows))
print("committed:", sum(row.disposition == "committed" for row in rows))

    A zero speculative count can be legitimate: the vote may resolve before a continuation is ready. Learn to distinguish this from a scheduling problem in timelines and diagnostics.
