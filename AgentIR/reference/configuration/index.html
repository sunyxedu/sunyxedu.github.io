    Runtime configuration¶

    These are the defaults in the checked-in AgentIR 1.3.0 implementation. Algorithm functions and CLI flags may override generation defaults; always inspect the effective settings of the entry point you use.

    Local runtime¶

    make_runtime takes keyword-only arguments:

    Argument Default Meaning
    model Required Main model identifier
    engine_args None Additional validated vLLM engine configuration
    devices None Main engine GPU visibility
    judge_model None Separate judge model; otherwise judge aliases main
    judge_engine_args, judge_devices None Judge-specific configuration
    judge_process False Managed separate judge-server process, text wire only
    judge_server_attach None Attach a judge-server endpoint instead of spawning it
    max_inflight 32 Per-engine AgentIR request capacity
    spec None Use the SpecConfig defaults below
    run_seed 20260708 Root seed for invocation and node seed derivation
    default_params None Override default generation parameters
    wire "text" "text" or "tokens"
    event_granularity "auto" Event observation policy
    chat_template_kwargs None Main chat-template options
    judge_chat_template_kwargs None Inherit main options; explicit {} resets them

    EngineSpec also exposes scheduling_policy="priority", enable_prefix_caching=True, reasoning_parser="auto", expected_version="0.24.0", and optional vllm_token_drafter. Its resolved physical configuration determines engine sharing.

    Remote runtime¶

    make_remote_runtime requires model and base_url, with the following additional options:

    Argument Default Meaning
    api_key, headers None Request authentication and headers
    expected_version "0.24.0" Required vLLM version; None removes only this version pin
    certificate_mode "required" Required Tier-1 contract
    expected_certificate_sha256 None Optional exact certificate pin
    request_timeout 900.0 HTTP request timeout in seconds
    render_cache_entries 128 Successful-render cache capacity
    thinking_token_budget None Optional supported server reasoning budget
    chat_template_kwargs None Certified rendering options

    max_inflight, spec, run_seed, and default_params have the same defaults as the local helper. The remote helper fixes the wire to tokens. Read remote execution for endpoint and capability requirements.

    Speculation configuration¶

    SpecConfig field Default Meaning
    enabled True Enable branch speculation
    window 2 Maximum eligible unresolved guard depth
    max_spec_inflight 8 Speculative request budget
    depth1_unmetered False Exempt depth-one work from that budget
    loop_lookahead None Reserved configuration field; current loop reads its own lookahead argument or derives its default from window
    decision_timeout 600.0 Seconds before an unresolved decision fails; None disables the watchdog
    op_drain_timeout 600.0 Seconds allowed for effect-obligation draining
    engine_restart_limit 1 Physical engine recovery limit
    judge_prefetch False Enable speculative prefix warming
    prefetch_chunk_tokens 64 Minimum new source tokens between warm requests
    prefetch_max_inflight 2 Dedicated prefetch lane capacity per engine
    static_plan None Compiled per-decision funding plan
    ev_gate False Fund speculation using estimated expected value
    ev_gate_p_floor 0.05 Cold-start probability floor for EV funding
    spec_preempt False Permit strictly better speculation to reclaim eligible slots

    window and max_spec_inflight do not replace max_inflight; physical capacity remains an independent limit. Turning speculation off also disables speculative prefix warming.

    Sampling parameters¶

    The runtime's base defaults are max_tokens=512, temperature=0.8, and top_p=0.95. The autonomous tool loop defaults to temperature zero unless overridden.

    The public parameter whitelist contains:

    max_tokens, temperature, top_p, top_k, min_p, logit_bias,
stop, stop_token_ids, repetition_penalty, frequency_penalty,
presence_penalty, logprob_topk, skip_special_tokens,
include_stop_str_in_output, structured

    Arbitrary vLLM sampling kwargs are not accepted. Parameters are copied into a canonical frozen representation before hashing. The DSL derives the seed and does not accept it as an ordinary sampling argument.

    structured must specify exactly one of json, regex, choice, grammar, json_object, or structural_tag. Availability also depends on adapter capabilities. Token drafting rejects min_p and logit_bias by key presence, even if supplied as zero or an empty mapping.

    Lifecycle methods¶

    Method Behavior
    run(fn, *args, problem_key="p0", invocation_key=None, **kwargs) Run a fresh tracing context, return its result, and drain effect obligations
    submit(fn, *args, ..., **kwargs) Return a concurrent future for lower-level asynchronous orchestration
    warm(timeout=3600.0) Load and handshake configured engines
    chat_prefix(messages, *, role="main", tools=None, generation=None, add_generation_prompt=True, timeout=600.0) Render with the selected engine's template
    ledger_for(problem_key) Return engine ledger rows for the label
    events_for(problem_key) Return recorded runtime events for the label
    close() Release runtime-owned threads, pools, and engines

    For custom construction, Runtime(models, ...) takes a role-to-ModelSpec mapping and optional role aliases. It defaults to 32 operation workers and 16 tracer workers. Nested invocations must leave enough workers for children to make progress; the subagent example documents that case.

    Source: runtime.py, engine.py, and parameter validation.
