    Command line¶

    Installing AgentIR adds the agentir command. Run agentir --help or agentir COMMAND --help for the parser's complete option list. The CLI uses the local model runtime; certified remote and Harbor workflows have their own Python and Harbor entry points.

    Commands¶

    Command Purpose Model required?
    agentir list Print registered algorithms and tasks No
    agentir warm Load and handshake the configured engine, then close it Yes
    agentir bench Run a dataset slice and report measurements Yes
    agentir refdiff Compare guarded lowering with the serial reference Yes
    agentir check Require both reference and scheduler differentials Yes

    Static compilation is available through agentir.compile.shape_trace, not a CLI subcommand.

    Engine options¶

    All model-executing commands require --model. Common options include --judge-model, --devices, --judge-devices, --judge-process, --max-model-len, --gpu-mem, --judge-gpu-mem, --max-inflight (32), and --wire (text).

    The CLI's --judge-process controls the dedicated scoring-server path. Token-wire and model compatibility still follow the runtime restrictions.

    Benchmark options¶

    bench requires --task and --algo:

    Option Default Meaning
    --task Required gsm8k, math500, aime2024, or amc2023
    --algo Required One of the eight built-in algorithms
    --n 10 Number of problems
    --offset 0 Starting position in the dataset
    --concurrency 1 Problems in flight
    --spec on on, off, both, ladder, or fastbase
    --out Unset JSONL run record path
    --dump-ledger DIR Unset Per-problem ledger output directory
    --runtime-graph [DIR] Unset Timeline output; optional value selects a directory

    Datasets are cached under ~/.cache/agentir. First access can download source data. both uses a fixed off-then-on order; ladder adds serial and oracle arms. fastbase runs a phase-alternating baseline, guarded speculation-off, and guarded speculation-on as three arms. The phase arm enables phase_serial; inspect the recorded algorithm configuration when comparing it with other arms.

    Speculation options¶

    --window 2 and --spec-inflight 8 set the depth and budget. Optional flags include --depth1-unmetered, --judge-prefetch, --ev-gate, and --spec-preempt. --prune-margin configures the beam predictor where supported.

    These flags address different mechanisms; see prediction and optimization before enabling several together.

    Algorithm options¶

    Option Default Typical use
    --k 6 Candidate count for sampling algorithms
    --width, --branch, --rounds 2, 2, 3 Beam shape
    --iters 4 Refinement or MCTS iteration bound
    --step-tokens 160 Per-step or rollout budget
    --late-step-tokens Unset Optional later-step budget
    --early-steps 3 Steps before the later budget takes effect
    --step-stop Unset Step delimiter
    --max-tokens 512 Main output budget
    --judge-tokens 96 Judge generation budget
    --scorer logprob logprob, judge, or prm
    --prm-agg min min, last, mean, or prod
    --temperature, --top-p 0.8, 0.95 Sampling settings
    --run-seed 20260708 Runtime seed

    --no-explain disables self-consistency's explanation. --chat uses chat-formatted prompting. --phase-serial introduces algorithm phase barriers. --bound-commit requires the supported scoring and step-boundary conditions; it changes the early-stopping contract in both arms.

    Options are dispatched according to the selected algorithm, so a shared parser option is not evidence that every algorithm uses it.

    Check options and exit status¶

    check defaults to --task gsm8k --algo beam_search; refdiff defaults to --task gsm8k --algo best_of_n. Both accept --offset. check --runtime-graph [PATH] renders the compared runs, and --slow-tool-audit additionally repeats declared-speculable tools for an observation audit.

    Successful checks exit zero. Semantic mismatches and setup failures exit nonzero. Automation should check the process status and preserve the report, not infer success from the existence of an output file.
