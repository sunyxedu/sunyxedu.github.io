    Timelines and diagnostics¶

    A timeline explains where an invocation waited, what ran early, and which work survived. Start with one problem before aggregating a benchmark: a wall-time number alone cannot show whether the expected overlap occurred.

    Render a runtime ledger¶

    After runtime.run(program, problem_key="example"), while the runtime is available:

    from agentir import render_timeline
from agentir.diagnostics.viz import TimelinePanel

rows = runtime.ledger_for("example")
render_timeline(
    TimelinePanel(label="Speculation on", rows=rows),
    "timeline.svg",
    title="One AgentIR invocation",
)

    render_timeline writes a standalone SVG without a plotting dependency. TimelinePanel is imported from its canonical diagnostics module. Supply a sequence of panels to compare runs on a shared time scale; optional runtime events add operation and decision lanes.

    For CLI runs, --runtime-graph writes timelines and --dump-ledger DIR saves per-problem ledger JSON. See the CLI reference.

    Read the timestamps in order¶

    Ledger field Meaning A long gap can indicate
    t_reg Node registered in the graph The tracer has exposed possible work
    t_data_ready Required input data became available Upstream generation, an operation, or observation is still needed
    t_issue Physical request issued Funding, priority, or engine capacity delayed ready work
    t_first First observed engine output event Prefill or engine queueing; interpret with event granularity
    t_done Request finished Generation or service time
    t_guard_resolved Keep-or-cancel condition resolved Selection or loop decision latency

    Some records are registered but never issued, and some adapters expose only terminal semantic events. Do not treat absent or terminal-only first-event timing as a measured first-token latency.

    Separate execution from usefulness¶

    speculative says how the request was issued. disposition says what happened to its work:

    • committed: part of the surviving computation.
    • wasted: executed or registered in a rejected world.
    • failed: ended in a relevant failure.

    A request can be issued speculatively and later commit. It can also complete early and then be discarded. Count useful lead separately from total speculative work.

    cached_tokens reports engine-observed cached prompt tokens. A value of zero means no reported cache hit; -1 means the information was unavailable. Neither a shared symbolic prefix nor fork_parent alone proves a physical cache hit.

    Diagnose a disappointing run¶

    Observation Inspect next
    No speculative requests issued Whether the decision resolved before input data; window and budget settings
    Ready work waits while the engine is full Committed load, per-engine capacity, and speculative interference
    Most speculative tokens are wasted Candidate count, guard depth, decision quality, and predictor hit rate
    Correct predictions save little time Tool latency, remote terminal boundary, render cost, and continuation length
    A large lead sum produces little wall-time gain Overlapping leads, resource contention, and other critical-path work
    Cache metrics disappear Engine capability and telemetry coverage, not just prefix construction

    The summed interval between speculative issue and guard resolution is a lead metric. Multiple requests can accumulate lead over the same wall-clock interval. Do not report that sum as elapsed time saved.

    Use telemetry for the right question¶

    bench.gpu_telemetry samples GPU metrics and validates the coverage of its output. bench.vllm_metrics_telemetry captures server metrics, including scheduler and KV-cache observations where available. Experiment scripts preserve raw samples and generate checked summaries.

    Low GPU utilization or apparent request underfill can be useful signals, but they are proxies. They do not by themselves prove an engine “bubble,” explain causality, or attribute a slowdown to one policy.

    Continue with benchmarking to turn individual traces into a controlled comparison.
