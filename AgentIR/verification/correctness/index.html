    Correctness checks¶

    Before asking whether speculation is faster, establish that the same logical program survives. AgentIR provides two complementary checks: one for the tracer's lowering, and one for speculation-on versus speculation-off scheduling.

    The two gates¶

    Gate Comparison What it tests
    A: reference differential Guarded speculation-off execution versus an independent serial source interpreter Whether guarded lowering preserves source-level selection and effects
    B: scheduler differential A captured off arm versus a fresh speculation-on runtime Whether speculative scheduling preserves the committed computation

    agentir refdiff runs the reference differential. agentir check requires both gates to pass. A failed check exits nonzero; a fast run with a failed gate is not valid performance evidence.

    Run the checks¶

    With a working engine installation:

    agentir refdiff \
  --model Qwen/Qwen2.5-0.5B-Instruct \
  --algo best_of_n --task gsm8k --offset 0

agentir check \
  --model Qwen/Qwen2.5-0.5B-Instruct \
  --algo beam_search --task gsm8k --offset 0 \
  --runtime-graph check.svg

    These commands load a model and may fetch the selected dataset into the task cache. Use a model and engine capacity suitable for the algorithm. The SVG shows the compared runtime schedules on a shared time scale.

    Why a serial interpreter is necessary¶

    Turning speculation off still uses guarded lowering. If the tracer constructs the wrong graph, both on and off arms could agree on the same bug.

    The serial interpreter instead follows decisions before constructing their selected continuation. It shares canonical identity construction with the runtime, but does not use the speculative hoisting execution path. Comparing the two checks that they identify the same surviving work.

    Gate A records engine outputs from the guarded arm and replays them through the serial interpreter. This isolates lowering correctness from engine nondeterminism. Missing replay entries fail closed.

    What the scheduler comparison observes¶

    Gate B uses a fresh speculation-on runtime and checks committed identities, prompt/output atoms and text, final results, failure behavior, and tool semantics against the captured off arm. Request-attempt histories may differ; the committed computation must still satisfy the comparison contract.

    Tool bodies are recorded in the first arm and replayed in the comparison arm. There is no fallback that quietly executes an unrecorded effect. This avoids repeating unknown effects merely to perform a differential check.

    Replay establishes a controlled semantic comparison. It does not establish that a changing external tool would return the same result when invoked again, or that seed equality alone guarantees bitwise engine reproducibility on every platform.

    Audit declared-speculable tools¶

    agentir check --slow-tool-audit additionally re-executes completed tools declared effect="speculable" and compares exact observation-image bytes. Unknown-effect tools are never rerun by this audit.

    The audit deliberately repeats declared-safe executions. A mismatch can reveal an unstable projection, hidden state, or an invalid speculability declaration. Use the normal record/replay check when you only need the lowering and scheduling comparison.

    Account for algorithmic truncation¶

    With a valid bound-commit algorithm, losing candidates can end at different permitted prefixes. Diagnostics distinguish that permitted truncation from changed surviving bytes. The same bound rule must be enabled in both arms, and the proof must ensure those truncated bytes do not affect a surviving result.

    Read score-bound truncation before treating a prefix difference as harmless.

    Tests and real-engine evidence¶

    The test suite includes deterministic fake engines and HTTP fixtures for ordering, retries, identities, protocol failures, and graph behavior. These make edge cases reproducible without a GPU. Other tests and scripts exercise real vLLM capabilities.

    A passing engine-independent suite does not replace an integration run on the actual model, parser, and server configuration. Record which checks ran and which engine-dependent checks were unavailable.

    Source: reference.py, tool_audit.py, and CLI gate tests.
