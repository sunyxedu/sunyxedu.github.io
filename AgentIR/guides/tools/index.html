    Defining tools¶

    A tool adds two contracts to a program: when its body may run and what the model gets to see of its result. Declare both. A result that is easy to predict says nothing about whether the side effect is safe to repeat.

    A tool the model can call¶

    from agentir import Exact, ToolDef, force, infer, make_runtime, out_text

CAPITALS = {"France": "Paris", "Japan": "Tokyo"}


def lookup_capital(args):                 # one dict argument, not kwargs
    return CAPITALS.get(args["country"], "Unknown")


def program():
    reply = infer(
        "Use the lookup tool to find the capital of France.",
        tools={
            "lookup_capital": ToolDef(
                lookup_capital,
                effect="speculable",
                obs=Exact(),
                description="Look up a country's capital.",
                input_schema={
                    "type": "object",
                    "properties": {"country": {"type": "string"}},
                    "required": ["country"],
                    "additionalProperties": False,
                },
            ),
        },
        max_turns=4,
        max_tokens=128,
    )
    return force(out_text(reply))


if __name__ == "__main__":
    with make_runtime(model="Qwen/Qwen3-Coder-30B-A3B-Instruct", wire="tokens") as runtime:
        print(runtime.run(program))

    infer(task, tools=...) runs the autonomous loop: render the conversation with the model's chat template, stream the assistant turn through vLLM's parser for that model family, execute the calls, feed back observations, repeat for up to max_turns. It returns the final assistant turn as a Seq. The loop requires wire="tokens" and a model from a supported family. input_schema is the JSON Schema of the argument object; AgentIR adds the provider's function wrapper.

    Choose the effect class¶

    effect Body runs Promise you make
    "unknown" (default) only after the turn that called it has committed; once; no retries none
    "speculable" as soon as the tool scheduler admits it, possibly for a branch that later loses; up to three tries per phase re-running and discarding is harmless

    An in-memory lookup is speculable. A shell command, a payment, a file write, or a query against changing data is unknown unless you have decided otherwise. The Harbor shell tool is unknown. Remember that a Python body which has started cannot be stopped; cancellation only prevents an unstarted body from being delivered.

    Choose what the model observes¶

    The policy maps the raw return value to an image (a string, or JSON rendered canonically), and declares which candidate images may stand in for it before the tool finishes.

    Policy Image When
    Exact() the projected result; guesses must match byte for byte the full result matters
    Ignore(text="done") a constant; never reads the result only completion matters
    Project(alpha) alpha(raw) the model needs a stable subset (a status code, a summary field)
    Enum(cases, by=key_fn) one of the declared representatives, or the real result through a hole() case the outcome space is finite and part of the tool's interface

    Ignore and Project change what the agent knows. They are semantic choices, not shortcuts.

    Add a prediction¶

    ToolDef(lookup_capital, effect="speculable", obs=Exact(), guess="Paris")

    While the tool runs, the next assistant turn is decoded against "Paris". When the real image arrives the loop compares bytes: a hit keeps that turn, a miss squashes it and decodes the turn against the real image. With an unknown-effect tool the body still waits for commitment, but the predicted next turn can overlap it once the calling turn is committed.

    A guess can also be a callable (state, call) -> str | Val | Seq, including one that traces DSL calls to a draft model. Predictor code runs in an advisory scope: model requests and speculable tools are allowed, unknown effects are not. A predictor that is still running when the real observation lands is abandoned.

    The default predictor

    ToolDef(fn) with neither obs nor guess gets Exact() plus a default draft predictor (a 32-token same-role sample, two candidates at first, calibrated online). Passing obs=Exact() explicitly, or guess=None, turns the predictor off. Keep this in mind when reading request counts in a benchmark.

    Tools placed directly in the graph¶

    When the program, not the model, decides to call a tool:

    from agentir import cat, expect, force, infer, lit, obs, observe, tool, out_text

def program():
    t = tool(lookup_capital, {"country": "France"}, name="lookup_capital", effect="speculable")
    guessed = expect(t, "Paris")                        # Choice: hit branch or real-image branch
    reply = infer(cat(lit("The lookup returned: "), guessed), max_tokens=48)
    return force(out_text(reply))
    • obs(t) splices the image into a prompt as a late-binding segment.
    • observe(t) returns the structured image as a Val for Python code.
    • ack(t) resolves when the body finished, without reading anything.
    • expect(t, guess) is a hit-or-miss decision; classify(t, cases) routes an exact image through a closed mapping and treats anything else as an error.
    • after= orders one tool behind other tools or ops without consuming their values or failures.

    Arguments may contain Val and Choice handles anywhere in the JSON tree; they resolve before the tool identity is hashed. A Seq is rejected: read it out with an exit first.

    Bounds¶

    max_turns bounds assistant rounds. max_calls (default 8) bounds the number of call slots the loop pre-reserves per turn for early dispatch; more calls than that are still executed, at a barrier. Neither is a safety limit on external actions; put that in the tool body.

    The mechanics behind all of this, including the streaming parser and the round template, are in Tools and the tool loop.
