    Tools and observations¶

    A tool adds two separate contracts to an agent program: when its body may execute, and what information its result contributes to the conversation. Define them separately. A predictable result does not make a side effect safe to repeat.

    Define a tool¶

    The public autonomous loop is infer(task, tools=..., max_turns=...). It uses the token wire and the engine's own chat template and tool parser.

    This complete example exposes an in-memory lookup. Replace the model with a supported tool-capable model that fits your environment:

    from agentir import Exact, ToolDef, force, infer, make_runtime, out_text

CAPITALS = {"France": "Paris", "Japan": "Tokyo"}


def lookup_capital(args):
    return CAPITALS.get(args["country"], "Unknown")


def program():
    response = infer(
        "Use the lookup tool to find the capital of France.",
        tools={
            "lookup_capital": ToolDef(
                lookup_capital,
                effect="speculable",
                obs=Exact(),
                description="Look up a country's capital in a small local table.",
                input_schema={
                    "type": "object",
                    "properties": {"country": {"type": "string"}},
                    "required": ["country"],
                    "additionalProperties": False,
                },
            ),
        },
        max_turns=4,
        max_tokens=128,
    )
    return force(out_text(response))


if __name__ == "__main__":
    with make_runtime(
        model="Qwen/Qwen3-Coder-30B-A3B-Instruct",
        wire="tokens",
    ) as runtime:
        print(runtime.run(program))

    The callable receives one argument dictionary, not keyword arguments. input_schema is the JSON Schema for that dictionary; AgentIR adds the provider's function wrapper. The returned Seq is the final assistant turn of the tool loop.

    Decide whether execution can be speculative¶

    effect When the body can run Your contract
    "unknown" (default) After its guard is true and required ordering has settled The runtime must fence external effects and avoid speculative execution
    "speculable" Under a pending guard, within the tool budget Extra executions and retries are safe; observations remain suitable for replay

    Reading a fixed in-memory table is a straightforward speculable tool. A shell command, payment, file write, or changing database query needs a deliberate effect decision. The Harbor shell tool uses "unknown".

    A running Python callable cannot be forcibly stopped in the general case. Cancellation can prevent a queued tool from starting, but it cannot undo a body that has already run. Unknown tools are not automatically retried. Speculable tools can be retried, so “read-only” alone may be too weak a contract if results depend on changing external state.

    Choose what the model observes¶

    The policy turns the raw tool result into an observation image and selects a declared candidate observation. Images are strings or canonically rendered JSON values.

    Policy Observation contract Useful when
    Exact() Preserve the actual image; guesses must match exactly The full result matters
    Ignore(text="done") Use a constant image without reading the raw result Completion matters, but result contents do not
    Project(alpha) Expose a pure projection of the result The model needs a stable subset or normalized form
    Enum(cases, by=...) Select among declared representatives or a real-result hole A finite set of outcomes is part of the tool's interface

    Ignore and Project deliberately define what information the agent receives. They are semantic choices, not approximate substitutes for an exact observation.

    Add a prediction¶

    A guess funds work against a possible observation while the real tool runs:

    tool_definition = ToolDef(
    lookup_capital,
    effect="speculable",
    obs=Exact(),
    guess="Paris",
)

    The loop verifies the projected real observation against the guess. A hit retains the candidate continuation; a miss uses the real observation. With an unknown-effect tool, the body still waits for commitment, but its predicted next model turn can overlap that body once the relevant conversation is eligible.

    Defaults depend on what you specify

    ToolDef(fn) supplies Exact() and a default model-based draft predictor. Supplying obs=Exact() explicitly disables that implicit predictor unless you also pass guess. Passing guess=None explicitly also disables it. This distinction matters for request budgets and baseline experiments.

    Advanced guesses can be callables that construct Val or Seq candidates, including ordinary DSL model calls. These are advisory computations: unknown effects are forbidden inside predictor construction. See prediction and optimization.

    Use tools directly in the graph¶

    When your program already knows the operation and its arguments, it can register a tool without asking the model to call it:

    from agentir import cat, expect, force, infer, lit, tool, out_text

def program():
    result = tool(
        lookup_capital,
        {"country": "France"},
        name="lookup_capital",
        effect="speculable",
    )
    observation = expect(result, "Paris")
    answer = infer(cat(lit("The lookup returned: "), observation), max_tokens=48)
    return force(out_text(answer))

    obs(handle) inserts a late-bound observation into a prompt spine. observe(handle) returns its structured projected value. ack(handle) waits for completion without reading content. classify routes exact projected images through a closed mapping; an unlisted result is an error, so use expect when misses need a fallback.

    Pass after= to impose execution ordering on a direct tool. Its predecessors must settle, but their values and failures are not injected into the new tool. If failure propagation is required, express that dependency explicitly.

    Bound the conversation¶

    max_turns bounds assistant rounds. max_calls bounds the speculative call-slot template for a round; the autonomous loop has an overflow barrier that handles the concrete calls at termination instead of silently dropping them. It is not a universal authorization limit on external actions. Use tool-side policy if your application requires such a limit.

    For custom observation policies and early dispatch mechanics, continue with streaming tool calls. For a real terminal integration, read Harbor.
