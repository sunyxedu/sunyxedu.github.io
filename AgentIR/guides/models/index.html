    Models, roles, and wires¶

    This page covers the local runtime: creating it, giving models roles, choosing a wire, rendering chat prompts, and freezing generation settings. The mechanics are in Engine adapters.

    Create a runtime¶

    from agentir import SpecConfig, make_runtime

runtime = make_runtime(
    model="Qwen/Qwen2.5-0.5B-Instruct",
    max_inflight=32,
    engine_args={"max_model_len": 2048, "gpu_memory_utilization": 0.5},
    spec=SpecConfig(window=2, max_spec_inflight=8),
)

    Weights load on first use or on runtime.warm(). engine_args forwards to vLLM's AsyncEngineArgs. max_inflight caps AgentIR requests per engine and is also passed as max_num_seqs, so the engine is sized to exactly what the scheduler will send. Prefix caching and priority scheduling are required and enabled by default; the engine refuses a configuration that turns them off.

    Roles¶

    Programs say model="main" or model="judge", never a model id. make_runtime creates main and aliases judge to it. Give the judge its own engine with any of:

    make_runtime(model=M, judge_model=PRM)                     # second model, same GPU
make_runtime(model=M, judge_devices="1")                   # same model, its own GPU
make_runtime(model=M, judge_model=PRM, judge_process=True) # subprocess server, own GIL
make_runtime(model=M, judge_model=PRM, judge_server_attach="http://127.0.0.1:8100")

    judge_process is worth it when two small engines in one interpreter serialize on the GIL; it is text-wire only and serves the one-token scoring workload. For more roles, build Runtime(models={role: ModelSpec(role, EngineSpec(...))}, role_aliases=...) directly. Engines are deduplicated by their full resolved configuration, so two roles with identical specs share one physical engine.

    Wires¶

    wire= Atoms Pick it for
    "text" (default) strings completion-style prompts, judge-server scoring
    "tokens" exact token-id tuples tool loops, chat and thinking models whose boundary tokens must round-trip exactly

    On the token wire, continuations are exact token prefixes and the tokenizer is the engine's own. Several engines may share a token wire only if their tokenizer programs are byte-identical; the runtime checks this at warm-up and refuses otherwise.

    Chat prompts¶

    Chat and thinking models need their template. Render it through the role's engine and pass the result to lit:

    prefix = runtime.chat_prefix(
    [{"role": "user", "content": "Explain why the sky is blue."}],
    role="main",
)

def program():
    return force(out_text(infer(lit(prefix), max_tokens=128)))

    chat_prefix returns a string on the text wire and a token tuple on the token wire (Harmony models always render to tokens). Pass tools= to render function schemas into the system turn. chat_template_kwargs on the runtime (and judge_chat_template_kwargs, which inherits from it unless set) is canonical, identity-bearing configuration. The built-in algorithms take chat=True to render their prompts this way.

    Generation settings¶

    Sampling parameters are validated and frozen into the node identity at trace time. Runtime defaults are max_tokens=512, temperature=0.8, top_p=0.95, overridable with default_params=. The accepted keys are listed in runtime configuration; anything else is an error rather than a silently dropped field. There is no per-call seed: it is derived from identity.

    structured= takes exactly one of json, regex, choice, grammar, json_object, structural_tag. In tool loops, structural tags are compiled in a preflight before the turn is admitted, so a grammar the engine rejects fails at trace time rather than mid-speculation.

    Two speculations, two switches¶

    SpecConfig.enabled controls AgentIR's branch speculation. vLLM's token drafting is an engine setting (EngineSpec(vllm_token_drafter={...}), or speculative_config in engine_args). They are independent and identity-bearing in different places: the drafter is part of the engine key, branch speculation is not part of any identity at all. A drafting engine rejects min_p and logit_bias by key presence. See four kinds of speculation.

    Event granularity¶

    event_granularity="auto" lets a committed request with no incremental consumer take one terminal stream event instead of one per engine step, which removes per-step host work on the loop thread. Speculative requests, streamed tool parsers, prefetch sources, and bound-commit targets keep the delta wire. Bytes are identical either way; only ledger t_first loses its first-token meaning for final-granularity attempts.
