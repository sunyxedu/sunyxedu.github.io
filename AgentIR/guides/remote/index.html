    Remote vLLM¶

    make_remote_runtime runs the tracer and scheduler on the client and delegates tokenization, chat rendering, generation, and tool parsing to a certified vLLM 0.24 server. The client needs neither vLLM nor a tokenizer. The protocol is AgentIR's own token-in/token-out contract, not the OpenAI chat API, so the server must run AgentIR's middleware.

    Launch the server¶

    Install the same AgentIR checkout into the server's vLLM environment so the middleware is importable, then:

    python -m vllm.entrypoints.openai.api_server \
  --model Qwen/Qwen3-Coder-30B-A3B-Instruct \
  --host 127.0.0.1 --port 8000 \
  --enable-auto-tool-choice \
  --tool-call-parser qwen3_xml \
  --middleware agentir.execution.vllm_certificate.middleware \
  --scheduling-policy priority \
  --enable-prefix-caching \
  --generation-config vllm

    The tool parser must match the model family (the middleware only certifies audited parser pairs: hermes+qwen3, qwen3_xml, qwen3_coder+qwen3). Check the certificate route once the server is up:

    curl --fail http://127.0.0.1:8000/v1/agentir/tier1/certificate

    A 503 here means the server state could not be certified; read the message rather than working around it.

    Connect the client¶

    from agentir import force, infer, lit, make_remote_runtime, out_text


def program():
    return force(out_text(infer(lit("The capital of France is"), max_tokens=32)))


if __name__ == "__main__":
    with make_remote_runtime(
        model="Qwen/Qwen3-Coder-30B-A3B-Instruct",
        base_url="http://127.0.0.1:8000",
    ) as runtime:
        print(runtime.run(program))

    The remote runtime is always on the token wire and exposes main with judge aliased to it. Pass api_key= or headers= when the server requires them; a trailing /v1 on the URL is normalized away.

    What one request does¶

    Step Route Client-side guarantee
    handshake GET /v1/agentir/tier1/certificate version pin, served model, parser names, and certificate digest are checked; the instance id is remembered
    render POST /v1/agentir/tier1/render exact prompt token ids and the server's complete SamplingParams are frozen into the E-node's identity as a _remote_tier1 envelope
    generate POST /inference/v1/generate token in, token out, buffered SSE; cancellation closes the socket, which is vLLM's abort
    derender POST /v1/agentir/tier1/derender the server re-renders the original request, checks digests, and runs its completed-output parser
    tokenize /tokenize, /detokenize the token wire's encode and decode

    Every protected request carries the certificate digest and instance id as headers. A mismatch (412 or 428) is treated as engine death: the client fences everything issued against that instance, re-handshakes once, and either continues or poisons the engine's records with the cause. expected_certificate_sha256= pins a deployment exactly for a controlled experiment.

    The streaming boundary¶

    Remote mode publishes tool calls after generation and derendering finish. It does not deliver the in-process adapter's mid-decode call events, because the parser lives on the server and only runs on completed output. A predicted next turn can still overlap the real tool execution once the call is known, so the second overlap of the tool loop is kept and the first is not. Keep this in mind when comparing local and remote latencies.

    Structural-tag constraints cannot be preflighted remotely, so the client refuses them rather than risk admitting a request the server's grammar compiler will reject.

    Caching and connections¶

    Successful renders are memoized in a single-flight LRU (render_cache_entries, default 128) keyed by certificate, instance, and canonical request. Ordinary JSON calls reuse pooled HTTP/1.1 connections; SSE connections are discarded after [DONE]. A restart or instance change clears the memo and the pool.

    The server side is documented in vllm_certificate.py; the client in remote.py. Both are exercised without a GPU by tests/test_remote_tier1.py and tests/test_vllm_certificate.py.
